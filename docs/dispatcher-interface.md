# Dispatcher interface checkpoint

October 13, 2026. The existing two-view local interface now presents a recovery proposal as a decision the dispatcher can inspect. It shows authoritative pending-proposal courier, quote, price, simulated arrival, deadline, spending limit and expiry separately from the agent explanation. Changed facts hide the old quote facts and approval controls; a new investigation still requires a fresh proposal and approval. Assignment, simulated pickup and simulated delivery remain distinct.

Both views use the same case-state rules. Rejected, escalated and assigned incidents omit obsolete decision/investigation controls. An approval recorded before assignment is visible as approval pending completion. Business history is readable in operation order; the escaped complete audit and diagnostics remain available in collapsed details. Credentials, exact-origin authorization, the same-origin referrer policy, model profile and spending guard are retained.

## Defects and verification

- **AGENT-017 — misleading decision controls.** The inherited detail template offered approval whenever a proposal existed without an assignment, including stale, rejected and escalated cases. The backend rejected unsafe assignments; the screen did not explain why. Red checks reproduce the offered actions; the corrected display derives action availability from freshness and terminal state. Terminal label improvements refine AGENT-002 and are not another defect count.
- **AGENT-018 — mixed database reads.** The independent reviewer reproduced three interleavings: commit between assignment/freshness reads, pickup between custody/assignment reads, and commit between view/history reads. A page could combine incompatible status, custody, controls and history. One read transaction now materializes snapshot, proposal, approval, assignment, terminal state, audit and counters. Proposal freshness uses the same pure policy as the commit service against that snapshot. Three real-database threaded regressions failed before the correction and pass after it. These interleavings are controlled test scheduling, not deliberately introduced product defects.
